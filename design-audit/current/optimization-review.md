# Zoom98 Control 优化审查

## 范围

- 用户目标：在 Mac 上可靠地配置 Zoom98 的灯光、键位、文本宏和屏幕模块。
- 证据：用户提供的键位页截图，以及当前 SwiftUI、VIA/HID、BLE 实现。
- 限制：截图产生于最近一次响应式缩放修复之前；键盘导航、VoiceOver、真实热插拔和跨固件兼容性没有完成实机测试。

## 当前优势

1. 实体键盘与真实 Zoom98 分区已经建立直接对应，改键入口明确。
2. 改键、文本宏与灯光保存的持久化含义已分开。
3. USB VIA 与 BLE Screen 被拆成不同控制路径，调试日志可以折叠。
4. 未确认的侧灯协议没有被伪装成可用功能。

## 高优先级风险

1. **写入后没有读回校验。** 改键、灯光和宏只根据发送成功更新界面；固件忽略或转换键码时，应用仍可能显示成功。
2. **导入配置缺少预检和事务保护。** 当前会逐键直接写入，没有先确认硬件、协议、布局、容量，也没有失败回滚；中途失败可能留下半套配置。
3. **HID 通信阻塞主线程。** 读取一层需要顺序请求整个 7×17 矩阵；无响应时理论上会长时间冻结界面。
4. **HID 响应没有严格关联请求。** 当前取收到的第一包，没有按命令类型验证；异步或无关报告可能被误认成响应。
5. **设备热插拔恢复不足。** 传输层没有移除回调和可靠重连，拔插或睡眠唤醒后可能需要重启应用。

## 中优先级机会

1. 写入前自动保存快照，并提供“撤销上一次改键”。
2. 配置备份覆盖所有层，而不是只导出当前层；JSON 中加入 VID、PID、协议和硬件版本。
3. 文本宏增加实时 ASCII/字节容量提示，并明确提醒不要保存密码。
4. 隐藏或隔离 18–31 号未确认灯效，避免普通用户把未知值当成已验证功能。
5. USB 主控、BLE 屏幕、HID 电量分别显示连接状态，避免“已连接 Zoom98”语义模糊。
6. 增加诊断包导出：应用版本、协议版本、固件版本和经过裁剪的日志，不包含宏内容。

## 发布与可访问性

1. 当前应用是临时签名且未公证，朋友使用时可能被 Gatekeeper 阻止。正式分发应使用 Developer ID 签名、公证并制作 DMG。
2. 实体键盘上的小字号和低对比次要信息存在可读性风险。
3. 尚未验证完整键盘操作、焦点顺序、VoiceOver 标签和“减少动态效果”设置；灯光预览应尊重系统减少动态效果选项。

## 建议顺序

1. 可靠写入：读回校验、失败提示、撤销。
2. 安全导入：兼容性预检、全层备份、失败回滚。
3. 通信稳定性：后台串行队列、请求匹配、热插拔恢复。
4. 宏容量与未知灯效整理。
5. 发布签名、公证和 DMG。
